# big-brain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build the approved wiki memory: a background updater digests interactive sessions into two markdown wikis, and every session gets the wiki indexes injected.

**Spec:** [docs/superpowers/specs/2026-11-21-big-brain-design.md](../specs/2026-11-21-big-brain-design.md) (Approved). The spec wins on any conflict.

**Architecture:** Pure helpers live in `lib/big-brain.ts`. The extension `extensions/big-brain.ts` registers sessions, starts the supervisor and injects the block. The supervisor `lib/big-brain-run.ts` runs one transaction per spawn. The guard `lib/big-brain-guard.ts` is a Pi extension loaded only into the child with `-e`.

**Tech stack:** Node v26 (runs `.ts` directly via type stripping), `node:test`, the Pi extension API, `git`.

## Deviations from the spec (deliberate, minimal)

- **Guard path.** The guard file is `lib/big-brain-guard.ts`, not `extensions/big-brain-guard.ts`. `package.json` sets `pi.extensions: ["./extensions"]`, and Pi auto-loads every `*.ts` in that dir (`docs/extensions.md:131`). In `extensions/`, the guard would block write/edit in every session.
- **Paseo-driven jobs.** Paseo-driven jobs (`news_api/run_report.sh`) get `--env PI_BIG_BRAIN=off` on `paseo run`. The spec's "launcher sets PI_BIG_BRAIN=off" means exactly this. The edit is in a separate repo (`~/news_api`), so it gets its own task and commit there.

## Conventions (all tasks)

- **Imports:** use `.ts` extension imports (`from "../lib/big-brain.ts"`), the same as `extensions/agent-forum.ts:22`. Import the Pi API types from `@earendil-works/pi-coding-agent`.
- **Comments:** no comments beyond a one-line "why". Use `shortcut:` comments exactly as in the spec.
- **Tests:** run with `node --test tests/<file>.test.ts`. Temp dirs come from `mkdtemp` and are removed in `after()`, as in `tests/agent-forum.test.ts:25-26`.
- **Paths:** never touch a real `~/.pi/agent/wiki*` from tests. Every function takes explicit dirs or a `home` param.
- **Secret scan:** reuse `looksSecret` from `lib/forum.ts:27`. Do not write a second regex set.

```ts
export const CHUNK_BYTES = 60 * 1024;
export const INDEX_CAP = 2048;
export const MAX_PAGES = 20;
export const MAX_PAGE_LINES = 40;
export const GLOBAL_TYPES = ["preference", "environment", "lesson"] as const;
export const PROJECT_TYPES = ["decision", "gotcha"] as const; // plus the fixed name overview.md

export type Entry = { type: string; id: string; timestamp?: string; message?: { role?: string; content?: unknown } };
export type Reg = { sessionFile: string; projectRoot: string | null; pid: number };
export type SessState = { marker: string | null; failures: number; status: "active" | "done" | "skipped" };
export type State = Record<string, SessState>;

export function isOff(env = process.env): boolean;                 // env.PI_BIG_BRAIN === "off"
export function stateDir(home = homedir()): string;                 // ~/.pi/agent/wiki-state
export function globalWiki(home = homedir()): string;               // ~/.pi/agent/wiki
export function projectWiki(projectRoot: string): string;           // <root>/.pi/wiki
export function parseEntries(raw: string): Entry[];                 // JSONL, bad lines skipped
export function sliceAfter(entries: Entry[], marker: string | null, end: string): Entry[]; // (marker, end]; marker null = from start
export function userCount(entries: Entry[]): number;
export function condense(entries: Entry[]): string[];               // one string per kept entry; see rules below
export function chunk(parts: string[], max = CHUNK_BYTES): string[];// join at entry boundaries; a single part > max is cut to max-12 bytes + "\n[truncated]"
export function citation(sessionFile: string, sessionId: string, date: string): string; // "[s:2026-11-21 a1b2c3]"
export function workerPrompt(firstUser: string): boolean;           // startsWith Orca dispatched-worker preamble or "<paseo-system"
export function digestible(env: NodeJS.ProcessEnv, hasUI: boolean, firstUser: string): boolean;
export function areas(projectRoot: string): string[];               // lowercase top-level dir names (no dot-dirs) + "db" + "cross"
export function validPageName(name: string, kind: "global" | "project", areas: string[]): boolean;
export function validateWiki(dir: string, kind: "global" | "project", areas: string[]): string | null; // null = ok, else reason
export function injectBlock(globalIndex: string | null, projectIndex: string | null, globalDir: string, projectDir: string | null): string; // "" when both empty
export function regFile(home: string, sessionFile: string): string; // wiki-state/sessions/<sha1>.json
export async function writeAtomic(path: string, data: string): Promise<void>; // tmp + rename, mkdir -p
```

Rules:

- **`condense`.** A `user` message becomes `USER: <text parts joined>`. An assistant message gives `ASSISTANT: <text>` for its text parts, plus `TOOL <name>: <first 200 chars of JSON.stringify(arguments)>` per toolCall. `toolResult`, `custom`, `model_change` and the other types are dropped. Skip empty strings.
- **`workerPrompt`.** True if `firstUser.startsWith("You are working inside Orca, a multi-agent IDE. You are a dispatched worker")` or `firstUser.trimStart().startsWith("<paseo-system")`.
- **`digestible`.** False if `isOff(env)`, `!hasUI`, `env.ORCA_TERMINAL_HANDLE?.startsWith("structworker_")` or `workerPrompt(firstUser)`.
- **`validPageName`.**
  - Global: `^(preference|environment|lesson)-[a-z0-9-]+\.md$`.
  - Project: `overview.md`, or `^(decision|gotcha)-(.+)\.md$` where the captured rest starts with `<area>-` for some area in `areas` followed by at least 1 char of `[a-z0-9-]`. Use a prefix match so hyphenated areas like `internal-gitlab-api` work.
- **`validateWiki`.** Top-level entries may only be `index.md` and valid page names. Anything else fails: dirs, hidden files, other names. A `.git` dir in the global wiki is the only exception.
  - Caps: ≤ `MAX_PAGES` pages, and each page ≤ `MAX_PAGE_LINES + 10` lines (slack for "about 40").
  - Every page must pass `!looksSecret(content)` (import from `./forum.ts`).
  - Every `](x.md)` link in `index.md` must name an existing page.
- **`injectBlock`.** The exact block text from the spec "Reading" section.
  - Each index is cut to `INDEX_CAP` bytes at a line boundary.
  - Relative `](name.md)` links are rewritten to `](<dir>/name.md)`.
  - The subsection for a missing or empty index is omitted, and `""` is returned when both are empty.

## Task 2: `lib/big-brain-guard.ts` + tests

**Files:** create `lib/big-brain-guard.ts` and `tests/big-brain-guard.test.ts`.

```ts
export function allowedTarget(target: string, cwd: string, roots: string[]): boolean;
export default function (pi: ExtensionAPI): void; // pi.on("tool_call") → block write/edit unless allowedTarget
```

The `roots` come from `process.env.BIG_BRAIN_ROOTS`, split on `:`. Each root is `realpathSync`'d at load, and if `BIG_BRAIN_ROOTS` is unset or empty, every write/edit is blocked.

`allowedTarget` works like this:
- Resolve `target` against `cwd`. Reject the target if its raw form contains a `..` segment.
- Its basename must not start with `.`.
- Its parent must be exactly one of the roots, so nested paths are rejected. Compare with `realpathSync(parent)` for the nearest existing parent, plus a separator-aware check: `p === root || p.startsWith(root + sep)`, and here the parent must *equal* the root.
- If the target exists, `lstatSync(target).isSymbolicLink()` rejects it.

The handler is `pi.on("tool_call", (event, ctx) => ...)` (`docs/extensions.md:973-1010`). It checks `event.toolName === "write" || event.toolName === "edit"` and reads `event.input.path`, resolved against `ctx.cwd`. If `!allowedTarget` it returns `{ block: true, reason: "big-brain: writes are limited to the wiki staging dirs" }`. Other tools pass.

## Task 3: `lib/big-brain-run.ts` supervisor + tests (depends on Task 1)

**Files:** create `lib/big-brain-run.ts` and `tests/big-brain-run.test.ts`.

**CLI:** `node lib/big-brain-run.ts --mode catchup|session [--session <file>] [--final] [--project <root>]`. It runs `main(argv, realDeps)` only when `import.meta.main` is true (verified on Node v26.13.1). Everything is injectable for tests:

```ts
export type Deps = {
  home: string;
  runChild: (prompt: string, roots: string[], timeoutMs: number) => Promise<number>; // exit code
  bdMemories: (projectRoot: string) => Promise<string>;                               // "" if bd absent or no .beads/
  now: () => Date;
  pidAlive: (pid: number) => boolean;
};
export async function main(argv: string[], deps: Deps): Promise<void>;
export async function preflightAndApply(staged: string, live: string, hashes: Map<string, string>): Promise<"ok" | "conflict">;
```

Follow the spec "Supervisor run" steps 1–6 exactly:

1. **Lock.** Lock file `wiki-state/lock`, created with `open(..., "wx")` and holding the pid. If it exists, read its pid; if that pid is dead, unlink the lock and retry once, otherwise exit 0. Release the lock in `finally`.
2. **Global wiki.** `git init` it if missing.
3. **Pick sessions.**
   - Registration records come from `wiki-state/sessions/*.json`.
   - **session mode:** take the record whose `sessionFile` matches.
   - **catchup mode:** take records with the same `projectRoot` and a dead pid whose state `status` is neither `done` nor `skipped`.
4. **For each session:**
   - Parse the file and set `end` to the id of the last entry.
   - If `userCount(sliceAfter(...)) < 2`: when `final`, set `marker = end` and `status = "done"`; either way, skip to the next session.
   - Otherwise `chunk(condense(slice))`.
5. **Per chunk:**
   - Stage copies of the `index.md` and `*.md` top-level files of both wikis into `wiki-state/runs/<id>/{global,project}`. The project wiki is staged only if `<projectRoot>/.pi/wiki` exists. Record sha256 hashes of the live files.
   - Build the prompt: the spec "Updater rules", page types and areas (the list from `areas()`), the staging paths, both indexes, the `bd memories` output, the citation, and the chunk.
   - `runChild` with a 5 min timeout.
   - Exit 0 → validate both staged dirs with `validateWiki`, then `preflightAndApply`, then the global git step, then advance the marker.
   - On failure: `failures++`, append a log line, stop this session; 3 failures → `skipped`.
6. **Global git step.** `git add -A -- index.md '*.md'`, then commit only if `git diff --cached --quiet` exits 1. Use the message `big brain: <citation>` and pass `-c user.name=big-brain -c user.email=big-brain@localhost` so it works without a git identity.
7. **State writes.** Read-merge-write `state.json` via `writeAtomic` under the lock.
8. **Clean up** `runs/<id>` in `finally`.

Put the spec's `shortcut:` comment (half-published chunk, upgrade to a journal) verbatim above `preflightAndApply`.

**`preflightAndApply`.** First check every changed or deleted page. If the live hash differs from the recorded hash *and* the live content differs from the staged content, return `"conflict"` with nothing written. Otherwise rename the staged files into the live wiki, then delete the pages removed in staging.

**Real `runChild`.** `spawn("pi", ["-p","--no-session","--no-extensions","-e",<pkg>/lib/big-brain-guard.ts,"--model",model,"--tools","read,write,edit",prompt], {env:{...process.env, PI_BIG_BRAIN:"off", BIG_BRAIN_ROOTS: roots.join(":")}, stdio:"ignore"})`. Kill it on timeout. `model` comes from `~/.pi/agent/settings.json` `bigBrain.model`, default `fedora/memory-generate`. The flags are verified against `pi --help`: `--no-extensions` keeps explicit `-e` paths.

**Real `bdMemories`.** Run `bd memories` in projectRoot when `.beads/` exists; any error → `""`.

**Main-checkout helper.** Main-checkout resolution lives in Task 4, not here. The CLI receives `--project`.

## Task 4: `extensions/big-brain.ts` + tests (depends on Task 1)

**Files:** create `extensions/big-brain.ts` and `tests/big-brain-ext.test.ts`.

```ts
export function mainCheckout(cwd: string): string | null; // first "worktree " line of `git -C cwd worktree list --porcelain`; null if not a repo
export function spawnSupervisor(args: string[]): void;     // spawn(process.execPath, [<pkg>/lib/big-brain-run.ts, ...args], {detached:true, stdio:"ignore"}).unref()
export default function (pi: ExtensionAPI): void;
```

The factory:

- If `isOff()` is true, return immediately.
- **`session_start`:**
  - Compute `projectRoot = mainCheckout(ctx.cwd)`.
  - Read `globalWiki()/index.md`, and also `projectWiki(root)/index.md` when that dir exists.
  - Cache `block = injectBlock(...)`.
- **`before_agent_start`:**
  - On the first call only: if `ctx.sessionManager.getSessionFile()` exists and `digestible(process.env, ctx.hasUI, event.prompt ?? "")`, write `regFile` = `{sessionFile, projectRoot, pid: process.pid}` with `writeAtomic` (no lock), then `spawnSupervisor(["--mode","catchup","--project",root])`.
  - On every call: if `block`, return `{ systemPrompt: event.systemPrompt + "\n\n" + block }`.
- **`session_compact` and `session_shutdown`:** if registered, `spawnSupervisor(["--mode","session","--session",file,"--project",root, ...(final ? ["--final"] : [])])`.
  - `final` is true only for `session_shutdown` with `event.reason` of `quit`, `new`, `resume` or `fork`. On `reload` the same session continues, so the run is non-final.
  - After `new`, `resume` or `fork`, Pi re-runs `session_start` for the new session. The extension resets its first-call and registered state there.
- Every handler body is wrapped in try/catch and never throws.
- Check the exact event and ctx field names against `docs/extensions.md` (`before_agent_start` around line 615, `ctx.hasUI` around 1175, sessionManager around 1205).

**`<pkg>` path.** Use `fileURLToPath(new URL("../lib/big-brain-run.ts", import.meta.url))`.
